# QLoRA 기반 AI 면접관 프로젝트

## 1. 문제정의

### 왜 AI 면접관인가?

기업 채용 과정에서 AI 활용은 이미 실제 업무로 확산되고 있다. 고용노동부와 한국고용정보원의 2025년 기업 채용동향조사에 따르면, 직원 채용에 AI 도구를 사용하는 기업 중 69.8%가 AI 기반 인적성·역량 검사를, 46.5%가 AI 면접 또는 대면 면접 결과 활용을 사용한다고 답했다. 또한 취업 준비에 AI 도구를 사용해 본 청년은 42.3%였고, 이들 중 36.4%는 면접 준비에 활용했다. [고용노동부 조사](https://www.moel.go.kr/news/enews/report/enewsView.do?news_seq=18662)

취업준비생은 실제 AI 영상면접과 직무 면접을 대비해야 하지만, 자신의 이력과 프로젝트 경험에 맞는 질문을 혼자 준비하기 어렵다. 본 프로젝트는 지원자의 **직무와 경험**을 입력받아, 실제 경험을 검증하는 맞춤형 기술면접 질문 한 개를 생성하는 AI 면접관을 만든다.

### 목표

- 입력: 지원 직무와 프로젝트·기술·문제 해결 경험
- 출력: 해당 경험을 가장 직접적으로 검증하는 심층 면접 질문 1개
- 제외: 일반적인 기술 정의 질문, 이력에 없는 기술을 가정한 질문, 질문 여러 개를 나열하는 출력

## 2. 요구사항 분석 및 제약조건

### 요구사항

1. 데이터의 후보 질문 3개 중 경험과 가장 관련된 **Top-1**을 고른다.
2. 학습된 모델은 서비스 시 질문 한 개만 생성한다.
3. 원본 데이터셋 `datas/ai_interview_sft.jsonl`은 변경하지 않는다.
4. 사람의 수작업 라벨링이나 외부 API 없이 학습 데이터를 준비한다.

### Top-1 기준

이번 버전의 Top-1은 다음을 의미한다.

> 지원자의 `경험` 텍스트와 가장 의미적으로 가까워, 이력에 실제로 적힌 기술·의사결정·문제 해결을 직접 질문하는 후보

예를 들어 경험에 `Qdrant`, `Top-k=5`가 적혀 있다면 해당 항목을 구체적으로 묻는 질문이, 경험과 무관한 일반 AI 질문보다 높은 우선순위를 갖는다.

현재 구현은 로컬 BGE 임베딩의 cosine similarity로 세 후보를 점수화한다. 따라서 “경험 관련성”에는 적합하지만, 질문의 난이도나 면접관다운 날카로움 자체를 완벽히 판정하는 모델은 아니다.

### 제약조건: GPU VRAM 8GB

- 대형 모델의 full fine-tuning은 어렵다.
- LoRA의 adapter만 학습하고, 기본 모델 가중치는 고정해야 한다.
- 학습 중 activation 메모리를 줄여야 한다.
- 서비스에서는 생성 요청을 한 번만 수행해야 한다.

## 3. 설계

### 전체 흐름

```text
datas/ai_interview_sft.jsonl (원본 유지)
        │
        ├─ input: 직무 + 경험
        └─ output: 후보 질문 3개
                 │
                 ▼
      로컬 BGE 임베딩으로 경험-질문 유사도 계산 (CPU)
                 │
                 ▼
      가장 높은 후보 1개를 completion으로 선택
                 │
                 ▼
       QLoRA SFT: 경험 → 질문 한 개 생성 학습
                 │
                 ▼
    서비스: 직무 + 경험 → 면접 질문 한 개 생성
```

### 데이터 설계

원본 파일은 그대로 둔다. 노트북 실행 중에만 파생 학습 데이터를 만든다.

| 구분 | 내용 |
| --- | --- |
| 원본 입력 | `직무`, `경험`을 포함한 `input` |
| 원본 출력 | 번호가 붙은 후보 질문 3개 |
| Top-1 선택 | 로컬 `BAAI/bge-m3` 임베딩 모델, CPU 실행 |
| 학습 prompt | “경험을 바탕으로 심층 기술면접 질문 한 개만 생성하라” |
| 학습 completion | 선택된 후보 질문 한 문장 |

### QLoRA 설계

| 항목 | 설정 |
| --- | --- |
| 기본 모델 | `Qwen/Qwen3-1.7B` |
| 양자화 | 4-bit NF4 + double quantization |
| 학습 대상 | LoRA adapter만 학습 |
| LoRA rank | 16 |
| batch size | 1 |
| gradient accumulation | 8 |
| max length | 512 |
| 메모리 절약 | gradient checkpointing, `paged_adamw_8bit` |

8GB 환경에서는 1.7B 모델을 우선 기준선으로 사용한다. 성능 개선은 모델 크기를 무리하게 늘리는 것보다 데이터 수와 데이터 품질을 먼저 높이는 방식으로 진행한다.

## 4. 구현

구현 파일은 `5.qlora_-Copy1.ipynb`이다.

1. `datas/ai_interview_sft.jsonl`을 읽는다.
2. `output`에서 번호가 붙은 후보 질문 3개를 분리한다.
3. 경험 텍스트와 세 질문을 BGE 임베딩으로 변환한다.
4. cosine similarity가 가장 높은 질문을 Top-1으로 선택한다.
5. 선택 질문만 `completion`으로 만들어 `SFTTrainer`에 전달한다.
6. 학습 전·후에는 `test_questions`의 `직무`, `경험`을 넣어 질문 한 개가 생성되는지 비교한다.

`test_questions` 형식은 다음과 같다.

```python
test_questions = [
    {
        "직무": "백엔드 개발자",
        "경험": "FastAPI와 PostgreSQL로 주문 API를 만들고 Redis 캐시로 조회 지연 시간을 개선했다.",
    },
]
```

## 5. 테스트 및 검증

### 기능 검증

- 모든 원본 행에서 후보 질문이 정확히 3개로 분리되는가?
- 선택된 `completion`이 한 문장 질문인가?
- 학습 후 출력이 번호 목록이나 해설 없이 질문 한 개인가?
- 테스트 경험에 없는 기술을 모델이 임의로 가정하지 않는가?

### Top-1 품질 평가

학습에 사용하지 않은 직무·경험 사례를 준비하고, 다음 3점 척도로 평가한다.

| 평가 항목 | 1점 | 2점 | 3점 |
| --- | --- | --- | --- |
| 경험 관련성 | 경험과 무관 | 일부 관련 | 이력의 기술·결정과 직접 연결 |
| 구체성 | 일반론 질문 | 기술 언급만 있음 | 프로젝트의 선택·실험·문제 해결을 질문 |
| 검증 가능성 | 답변 역량 판단 어려움 | 일부 판단 가능 | 답변으로 실제 역량을 구분 가능 |

### LoRA와 QLoRA 비교

두 방식은 반드시 같은 조건에서 비교한다.

| 항목 | LoRA | QLoRA |
| --- | --- | --- |
| 기본 모델 저장 | bf16/fp16 | 4-bit NF4 |
| 학습 파라미터 | LoRA adapter | LoRA adapter |
| VRAM 사용량 | 상대적으로 큼 | 상대적으로 작음 |
| 8GB 적합성 | 기준선 실험용 | 실제 학습 권장 |

비교 지표는 다음과 같다.

- 최고 GPU VRAM 사용량
- 학습 시간
- OOM 발생 여부
- adapter 크기
- 동일 테스트 세트의 경험 관련성·구체성·검증 가능성 평균 점수

## 6. 개선 방향

1. **데이터 확장**: 현재 31개 데이터는 개념 검증 수준이다. 직무·경력·기술 스택·장애 해결·성과 수치를 다양하게 포함해 수백 건 이상으로 확장한다.
2. **Top-1 기준 고도화**: 현재 의미 유사도 외에 “구체성”과 “검증 가능성”을 별도 점수로 설계한다.
3. **데이터 검수**: 무작위 표본을 확인해, 임베딩이 단순 키워드 일치만으로 부적절한 질문을 고르지 않는지 점검한다.
4. **하이퍼파라미터 실험**: 데이터가 충분해진 후 `r=16`을 기준으로 `r=32`, max length, learning rate를 비교한다.
5. **출력 제어**: 질문 한 문장만 반환하는지 정규식·길이 제한으로 후처리 검증을 추가한다.
